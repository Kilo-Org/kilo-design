# Kilo Landing Design

Landing is Kilo's acquisition and explanation surface. It can be more expressive than Cloud or editor UI, but it should still feel like Kilo: concrete, developer-native, dark-first, and product-led.

## Intent

Landing should help developers understand what Kilo is, pick the right product path, and start using it quickly.

## Product Rules

1. Show the real product early. Hero and primary sections should reveal actual product states, terminal/editor surfaces, install choices, or agent workflows.
2. Keep yellow as the primary CTA color. Do not scatter yellow across decorative elements if it weakens the action hierarchy.
3. Marketing pages can use larger type and more space, but should still preserve Kilo's dark, neutral foundation.
4. Avoid generic SaaS ornament. Prefer product screenshots, terminal/editor visuals, concrete metrics, and direct installation surfaces.
5. Product-specific accents can appear in badges and comparison surfaces, but should follow the shared status/product color taxonomy.
6. Landing can be more atmospheric than app UI, but core CTAs, forms, pricing, install flows, and navigation should use shared tokens.

## Layout

- Hero moments can use display type.
- Product chooser and install flows should be compact and scannable.
- Pricing, FAQ, and docs-entry surfaces should use stable card and border rules.
- Mobile layouts should keep CTAs visible and avoid oversized decorative spacing.

## Copy

Prefer concrete claims, product names, and direct next steps. Avoid vague AI superlatives.
